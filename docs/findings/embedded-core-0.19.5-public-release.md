# Core 0.19.5 public release validation

This record concerns the public Core `0.19.5` Git commit `13ad7336de1e8be4eba95fbd673ccb448c612d03`, installed into a clean Bench environment. It is distinct from the earlier candidate `f289035` and its version-specific approvals. Bench package version remains the unreleased `0.3.12` candidate.

On CPython 3.12.16, 3.14.10 and 3.15.2 with PostgreSQL, 326 Bench tests passed without skips per version (before the added comparison unit test). The unmodified [raw frozen comparison](data/embedded-core-0.19.5-release-frozen-312-raw.json) reports 392 unchanged query signatures and the single previously identified `ac-q-c20` correction. On 16 November 2026 the user approved this exact result for the public release commit. The [reviewed rerun](data/embedded-core-0.19.5-release-frozen-312-reviewed.json) passes using the separate exact-commit manifest; original gold and raw failure are unchanged. Source diagnostics match and PostgreSQL source assessment passes 191/191 fixture checks.

The [raw three-backend comparison](data/embedded-core-0.19.5-release-threeway-312-raw.json) identifies exactly the three previously reviewed supporting-event order differences across SQLite, reopened SQLite and PostgreSQL. Other compared fields, recorded uses, metrics and source assessments match; repeated PostgreSQL mini also matches. The user separately approved the exact fingerprints for the public release commit on 16 November 2026. The [reviewed report](data/embedded-core-0.19.5-release-threeway-312-reviewed.json) passes without changing the raw data.

The Python 3.11 [raw comparison](data/embedded-core-0.19.5-release-frozen-311.json) preserves the 16 additional historical-gold differences. A [same-runtime comparison](data/embedded-core-0.19.5-release-frozen-311-paired.json) matches all 22 runs to the earlier Core baseline; it does not approve or explain those historical-gold differences. SQLite reopen in the three-backend comparison occurs in the same process. A separate Bench integration test now opens the same SQLite database in independent writer and reader processes and compares persisted recall identities, scores and reinforcement. It is a focused restart smoke test, not a fresh-process replay of every Bench workload. These approvals do not apply to a future 0.19.6 candidate. Each deterministic three-backend run requires a fresh dedicated PostgreSQL database: UUIDs are seeded for reproducibility, so unrelated pre-existing data can collide. An initial attempt on a previously used database failed for that reason; the documented result above is from an isolated empty database.
